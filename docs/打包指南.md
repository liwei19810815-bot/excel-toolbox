# 一键安装包 打包指南

面向**做打包发布的人**（通常是 IT）。业务用户不需要看这份文档，他们只需要包里的「使用说明.txt」。

打包这件事被收敛成了一条命令：

```powershell
powershell -ExecutionPolicy Bypass -File build\pack.ps1 -Mode loader -SharePath "\\fs01\tools\ExcelToolbox"
```

它做三件事：**从源码重新构建 → 组装成包 → 自检**。自检不过就不会生成 zip，
免得半成品躺在 `dist\` 里被人顺手发出去。

---

## 一、先决定：发哪种形态

这是整件事里唯一需要动脑的地方，选错了以后改起来很贵。

| | **loader（自动更新版）** | **standalone（独立版）** |
|---|---|---|
| 包里放的 | `ExcelToolboxLoader.xlam` 瘦加载器 | `ExcelToolbox.xlam` 本体 |
| 功能从哪来 | 启动时去共享目录取最新载荷 | 就在包里 |
| **以后升级** | **发一次载荷，全公司下次开 Excel 自动更新，不碰任何客户端** | 重新打包，挨个重装 |
| 需要 | 一个所有人都能读的共享目录 | 什么都不需要 |
| 适合 | 内网常规分发（**默认选它**） | 没有共享盘、人很少、或给外部/临时用户 |

选 loader 的话，`-SharePath` **写死在加载器里，装到客户端之后运行时改不了**
（不是没试过做成可配置：Excel 宏里 `WScript.Shell` 会被安全策略静默拦下，
表现是"更新莫名其妙不生效"且查不出原因，见 `src/loader/code/modLoader.bas` 的注释）。

> **换共享目录 = 重新打包 + 每台机器重装一次加载器。**
> 所以这个地址要在打包前确认好，别用临时路径试。

---

## 二、打包机需要什么

1. **装了 Excel**（打包要驱动 Excel 把源码编译进 .xlam）。
2. **开启"信任对 VBA 工程对象模型的访问"**。没开的话构建会失败并提示。
   路径：Excel → 文件 → 选项 → 信任中心 → 信任中心设置 → 宏设置 → 勾选它。
   *这是安全设置，请你自己在界面上改，脚本不会替你动它。*
3. **打包期间别去操作 Excel 窗口**——脚本正驱动着它。
4. 用 **PowerShell 窗口**运行，不要用 Git Bash 等外壳。
   原因见下面「UNC 路径被吃掉一个反斜杠」。

---

## 三、要先准备好的信息

| 信息 | 什么时候需要 | 说明 |
|---|---|---|
| 共享目录地址 | loader 模式 | 形如 `\\fs01\tools\ExcelToolbox`。所有用户要有**读**权限 |
| 内网网关地址 | 要带 AI 助手时 | 形如 `https://192.168.1.50:8443`，结尾不要带斜杠 |
| 内网 CA 证书 | 网关用自签证书时 | `.crt` 文件。不给的话任务窗格会因证书不受信任打不开 |
| 自己的 GUID | 正式分发 AI 时 | 换掉 `install\ai\manifest.template.xml` 里的示例 `<Id>`，见 `install\ai\README.txt` |

> **共享目录的写权限 = 对每一台客户端的代码执行权。**
> 能往那个目录放文件的人，等于能让全公司的 Excel 执行任意宏。
> 权限要按这个级别来管，别当成普通文件夹。

---

## 四、打包前必做：跑一遍验收

包里装的是什么，取决于当前源码。先确认源码是好的：

```powershell
powershell -ExecutionPolicy Bypass -File tests\run-all.ps1
```

全绿才打包。结果会写进 `docs\验收记录.md`，那份文件是可复核的凭证。

改了版本号的话，改的是 `src\code\Core\modApp.bas` 里的 `APP_VERSION`——
打包脚本从那里读版本，不接受手输，免得包名和加载器里记的版本对不上。

---

## 五、打包

**内网常规分发（推荐）**

```powershell
powershell -ExecutionPolicy Bypass -File build\pack.ps1 -Mode loader -SharePath "\\fs01\tools\ExcelToolbox"
```

**独立版**

```powershell
powershell -ExecutionPolicy Bypass -File build\pack.ps1
```

**带 AI 助手**（两种形态都可以叠加）

```powershell
powershell -ExecutionPolicy Bypass -File build\pack.ps1 -Gateway "https://192.168.1.50:8443" -CaCert "C:\certs\intranet-ca.crt"
```

产物：

```
dist\Excel工具箱_v1.0.0_自动更新版.zip     ← 发这个
dist\Excel工具箱_v1.0.0_自动更新版\        ← 解开的同名目录，方便你自己检查
```

包里是：

```
Excel工具箱.bat          用户双击这个（装和卸都是它）
Install-Toolbox.ps1      实际干活的脚本
ExcelToolbox*.xlam       加载宏本体或加载器
使用说明.txt             给用户看的
打包清单.txt             版本、形态、共享目录、每个文件的 SHA256
ai\                      只有带了 -Gateway 才有
```

`install\ai\README.txt` **不会**进包——那是给你看的，用户看了只会困惑。

## 六、自检在查什么，红了怎么办

自检查的每一条，都对应一个**在用户机器上才显形、而且报错完全不指向真因**的故障。

| 自检项 | 不查会怎样 |
|---|---|
| `Install-Toolbox.ps1` 是 UTF-8 with BOM | 中文机器按 GBK 读，脚本直接语法错误，用户看到一屏英文报错 |
| `Excel工具箱.bat` 是纯 ASCII | 换台机器控制台代码页不同，提示全是乱码 |
| `.xlam` 里有 `vbaProject.bin` | **宏丢了**。装得上、没报错、一个功能都没有 |
| `.xlam` 里有 `customUI14.xml` | 装上不出现「工具箱」选项卡（加载器除外，它的功能区随载荷下发） |
| 网关地址替换后仍是合法 XML | Office 遇到非法 manifest 是**静默不加载**，用户只看到"按钮没出现" |
| `gateway.txt` 无 BOM | BOM 混进地址，拼出来的 URL 是坏的，同样静默不加载 |
| 产物不比源码旧（仅 `-SkipBuild`） | 打出来的是上周的构建，没有任何征兆 |

**红了就是不能发**，脚本不会生成 zip，半成品目录留着给你排查。

## 七、发之前：在干净机器上实装一次

**自检只能证明文件对，证明不了它在别人的机器上装得上。** 这一步不能省：

1. 找一台**没装过**工具箱的机器（或先在测试机上完整卸载）
2. 解压 → 双击 `Excel工具箱.bat` → 回车
3. 打开 Excel，确认出现「工具箱」选项卡
4. 随便点一两个功能，再点「帮助」看看能不能打开
5. 再双击一次 `Excel工具箱.bat` 选卸载，确认能卸干净

**Mark of the Web**：zip 如果是通过邮件或浏览器下载来的，Windows 会给它打上网络来源标记。
建议在解压**之前**右键 zip → 属性 → 勾「解除锁定」。
（安装脚本会自己解除 `.xlam` 的标记——这一步不做 Excel 会直接禁用宏，
而且报错信息完全不提这回事。但 zip 整体的标记最好还是先去掉。）

## 八、loader 模式：别忘了发载荷

**只打包不发载荷，客户端装完是没有任何功能的**——加载器去共享目录取载荷，取不到就只能用本地缓存，而第一次装的人没有缓存。

```powershell
powershell -ExecutionPolicy Bypass -File build\publish.ps1 -SharePath "\\fs01\tools\ExcelToolbox"
```

发布是往共享目录**新增**一个带版本号的载荷文件，然后更新清单。
全程不覆盖正在使用的文件，所以**不需要要求大家关掉 Excel**。

**回滚**：把清单改回旧版本号即可，客户端下次启动自动退回去，不用动任何一台机器。

```powershell
powershell -ExecutionPolicy Bypass -File build\publish.ps1 -SharePath "\\fs01\tools\ExcelToolbox" -Version 1.0.0 -Rollback
```

以后的日常升级就只有这一条命令了，不再需要重新打包、更不需要碰客户端。

## 九、踩过的坑

**UNC 路径被吃掉一个反斜杠。**
在 Git Bash 等非 PowerShell 外壳里传 `\\fs01\tools\X`，到脚本里会变成 `\fs01\tools\X`。
这个地址是写死进加载器、运行时改不了的，一旦带着错地址发出去，
全公司的加载器都指向一个不存在的路径——**而加载器找不到共享目录时是静默用本地缓存，没有任何报错**。
脚本现在会拦下单反斜杠开头的路径并提示，但最稳妥的做法还是：**在 PowerShell 窗口里跑，路径用双引号括起来**。

**`-SkipBuild` 会打出陈包。**
它跳过构建直接用 `dist\` 里现成的产物。脚本会比对产物和源码的修改时间并拦住明显过期的情况，
但没有必要就别用这个开关——重新构建也就几十秒。

**示例 GUID 没换。**
两个组织用同一个加载项 `<Id>` 会互相覆盖，而这种冲突极难排查。打包时只会警告，不会拦。

**证书过期。**
到期后任务窗格直接打不开。脚本会解析证书并在 90 天内到期时提醒——
顺便也挡住了"把别的文件当成证书放进去"这种事（那个错误原本要等用户安装时才暴露）。
